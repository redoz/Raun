## 1. What & why

Raun lowers each `[Scenario]` method into a generated `RaunScenarios.g.cs` (class `Raun.Generated.RaunGenerated`): one `Scenario_X()` builder per scenario, each building a `ScenarioNode[]` whose nodes carry a `static async (__inputs, __ctx) => { … }` `Invoke` lambda. The scheduler runs those lambdas.

Today, debugging a scenario steps through the *generated* file. **Goal:** emit `#line` directives so that, under a debugger, a breakpoint on a step's DSL call (`When.CreateAppointment(...)`) binds to the developer's **original source line**, and stepping never descends into generated plumbing.

**Accepted caveats (settled, not open):**
- Only the *line* maps. Locals won't match — the generated body uses `__inputs.Get<T>(0)`, not the user's `patient`/`slot`. Out of scope.
- PDB sequence-point behavior is awkward to unit-test; we rely on compile-success + snapshots + a manual debugger checklist (see §7). An automated PDB assertion is a documented optional follow-up, **not** built here.

## 2. Design (the decisions)

**Approach A — `#line hidden` baseline + per-step bracket.** Default the whole generated file to `#line hidden` (emit it as the **last line of the `Header` raw-text const**, after `// <auto-generated/>`, `#nullable enable`, `#pragma warning disable CS1591`). Then bracket **only** the awaited-call statement inside each step's `Invoke` lambda:

```csharp
Invoke = static async (__inputs, __ctx) =>
{
#line 78 "C:\…\AppointmentTests.cs"
    var __r = await When.CreateAppointment(__inputs.Get<global::Demo.Patient>(0), __inputs.Get<global::Demo.Slot>(1));
#line hidden
    return (object?)__r;
}
```

Void steps map the bare `await …;` and put `#line hidden` on `return (object?)null;`. Everything else (node construction, `CreateAll`, the module initializer, `FormatDisplayName`, the `Scenario_X()` builder, the `__r`/cast/return boilerplate) inherits the file baseline `#line hidden` and is never stepped into. **No `#line default` is needed** because the baseline is `hidden`, not `default`. Approach A *fails safe* — anything we forget to annotate stays hidden rather than leaking into stepping — and minimizes snapshot churn.

**Mechanism — structured trivia first, raw-text fallback, gated on a spike.** The emitter builds nodes then `NormalizeWhitespace(eol:"\n")`s them. The one real unknown is whether `NormalizeWhitespace` renders a structured `LineDirectiveTriviaSyntax` correctly (own line, trailing newline, compiler-legal). **Task 1 is a throwaway spike that decides:**
- **Shape A (preferred):** attach `LineDirectiveTriviaSyntax` as leading trivia on the relevant tokens.
- **Shape B (fallback):** build the awaited statement via `ParseStatement` over text that already contains the `#line` lines, so directives enter as already-correct trivia.

The file-level baseline goes in the raw `Header` const either way (never passed through `NormalizeWhitespace`), so that directive is immune to the spike outcome.

**Path handling.** Use `step.SourceFile` **verbatim** (it's the compiler-derived path from `ScenarioParser.Location` → `GetLineSpan().Path`, which matches the PDB; do **not** relativize). Escape it via Roslyn `Literal(path)`. **Omit the per-step `#line N "file"`** when `string.IsNullOrEmpty(step.SourceFile) || step.SourceLine <= 0`.

**Why that keeps snapshots deterministic:** `GeneratorHarness.RunDriver` parses **without a path**, so `SourceFile == ""` in the existing snapshots. With the omission rule, the 3 existing snapshots gain *only* the baseline `#line hidden` + a per-return `#line hidden` — **no machine-specific `#line N "file"`**. The populated-path branch is proven separately by a new path-bearing harness overload (§ Task 3) that parses with a fixed `"Scenario.cs"` path.

**Scope / non-goals (YAGNI):** do **not** map `FormatDisplayName`, `Scenario_X()`, `CreateAll`, or the module initializer; do **not** change `ParsedScenario`/`ParsedStep`, `ScenarioParser.Location`, the analyzer, or runtime/model types; no `/pathmap` handling beyond Roslyn's default.

**Open assumptions to confirm before/while executing:**
1. Baseline = `#line hidden` for the whole file (Approach A), not "default file with hidden regions" (Approach B in the brainstorm). Chosen for fail-safe + low churn.
2. Scenario builder method and `FormatDisplayName` intentionally left hidden (no one wants to break on scenario *construction* or reporting).
3. Empty/zero `SourceFile`/`SourceLine` ⇒ omit the per-step directive (hence snapshots show no `#line N "file"`).
4. `step.SourceFile` used verbatim (absolute, compiler-derived), no relativization.
5. Mechanism picked by the spike; both shapes pre-approved.
6. Extending the harness with a path-bearing parse overload is acceptable.
7. Automated PDB sequence-point test deferred.

**If DECISION = Shape A (structured trivia)** — replace `BuildInvokeLambda` with:
```csharp
static ParenthesizedLambdaExpressionSyntax BuildInvokeLambda(ParsedStep step)
{
    var awaitExpr = AwaitExpression(ParseExpression(step.InvokeCallText));

    StatementSyntax callStmt;
    StatementSyntax returnStmt;
    if (step.HasResult)
    {
        callStmt = LocalDeclarationStatement(
            VariableDeclaration(IdentifierName("var"))
                .WithVariables(SingletonSeparatedList(
                    VariableDeclarator(Identifier("__r"))
                        .WithInitializer(EqualsValueClause(awaitExpr)))));
        returnStmt = ReturnStatement(
            CastExpression(NullableType(PredefinedType(Token(SyntaxKind.ObjectKeyword))), IdentifierName("__r")));
    }
    else
    {
        callStmt = ExpressionStatement(awaitExpr);
        returnStmt = ReturnStatement(
            CastExpression(NullableType(PredefinedType(Token(SyntaxKind.ObjectKeyword))),
                LiteralExpression(SyntaxKind.NullLiteralExpression)));
    }

    callStmt = callStmt.WithLeadingTrivia(LineMappedTrivia(step));
    returnStmt = returnStmt.WithLeadingTrivia(HiddenTrivia());

    return ParenthesizedLambdaExpression()
        .WithModifiers(TokenList(Token(SyntaxKind.StaticKeyword), Token(SyntaxKind.AsyncKeyword)))
        .WithParameterList(ParameterList(SeparatedList(new[]
        {
            Parameter(Identifier("__inputs")),
            Parameter(Identifier("__ctx")),
        })))
        .WithBlock(Block(callStmt, returnStmt));
}

static SyntaxTriviaList LineMappedTrivia(ParsedStep step)
{
    if (string.IsNullOrEmpty(step.SourceFile) || step.SourceLine <= 0)
    {
        return TriviaList();
    }
    var directive = LineDirectiveTrivia(Literal(step.SourceLine), Literal(step.SourceFile!), isActive: true);
    return TriviaList(Trivia(directive), EndOfLine("\n"));
}

static SyntaxTriviaList HiddenTrivia()
    => TriviaList(Trivia(LineDirectiveTrivia(Token(SyntaxKind.HiddenKeyword), isActive: true)), EndOfLine("\n"));
```

**If DECISION = Shape B (raw-text fallback)** — replace `BuildInvokeLambda` with:
```csharp
static ParenthesizedLambdaExpressionSyntax BuildInvokeLambda(ParsedStep step)
{
    var prefix = LinePrefix(step);

    StatementSyntax callStmt;
    ExpressionSyntax returnValue;
    if (step.HasResult)
    {
        callStmt = ParseStatement($"{prefix}var __r = await {step.InvokeCallText};");
        returnValue = IdentifierName("__r");
    }
    else
    {
        callStmt = ParseStatement($"{prefix}await {step.InvokeCallText};");
        returnValue = LiteralExpression(SyntaxKind.NullLiteralExpression);
    }

    var returnStmt = ReturnStatement(
            CastExpression(NullableType(PredefinedType(Token(SyntaxKind.ObjectKeyword))), returnValue))
        .WithLeadingTrivia(ParseLeadingTrivia("#line hidden\n"));

    return ParenthesizedLambdaExpression()
        .WithModifiers(TokenList(Token(SyntaxKind.StaticKeyword), Token(SyntaxKind.AsyncKeyword)))
        .WithParameterList(ParameterList(SeparatedList(new[]
        {
            Parameter(Identifier("__inputs")),
            Parameter(Identifier("__ctx")),
        })))
        .WithBlock(Block(callStmt, returnStmt));
}

static string LinePrefix(ParsedStep step)
{
    if (string.IsNullOrEmpty(step.SourceFile) || step.SourceLine <= 0)
    {
        return "";
    }
    var fileToken = Literal(step.SourceFile!).ToString(); // properly-escaped, quoted C# string literal
    return $"#line {step.SourceLine} {fileToken}\n";
}
```

## 6. Risks / iteration notes

- **Central unknown:** `NormalizeWhitespace` × directive trivia — resolved by the Task 1 spike with a pre-decided raw-text fallback (Shape B). If *neither* survives cleanly, last resort is splicing the awaited-statement region as raw text relative to a marker; the spike should make this unnecessary.
- **`LineDirectiveTrivia` API overloads** are the most likely compile-iteration point (see Task 1 note).
- **Determinism:** absolute paths are correct for consumers but vary by machine; they only ever appear in the consumer's (un-snapshotted) generated file and match the PDB. Snapshots stay machine-independent via the pathless/`"Scenario.cs"` split.

## 7. Manual debugger checklist (run once by a human; not automated)

Against the sample `AppointmentTests` in an IDE:
1. Breakpoint on a `When.CreateAppointment(...)` line in the original `*Tests.cs` → run the test → it binds and hits **on that original line** (not in `RaunScenarios.g.cs`).
2. Step Over / Step Into repeatedly → moves between original DSL call lines; never descends into `RaunScenarios.g.cs` plumbing (`CreateAll`, `Scenario_X()`, module initializer, `FormatDisplayName`, the `__r`/cast/return boilerplate).
3. Breakpoint on a void step (`Then.AppointmentExists(...)`) → binds to the original line and hits.
4. Locals showing `__r`/`__inputs` instead of the user's names is expected (accepted non-goal).
